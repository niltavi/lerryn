# Agent 自动化沙箱 PRD 初稿

版本：0.3 草案　日期：2026年11月2日

本产品是由外部 Agent 操作的自动化沙箱，面向企业自部署。Agent 通过 API 和 MCP 准备执行环境、维护任务、设置触发条件并处理失败；平台负责持续调度、隔离执行、凭证使用和运行记录。人通过 Web 和移动端的极简控制台查看状态、日志、结果和执行进展，必要时进入专用页面填写凭证。

产品名为 Lerryn。项目由个人维护代码，以 AGPL-3.0 开源，托管在 [github.com/niltavi/lerryn](https://github.com/niltavi/lerryn)；公司是首个实际使用场景。初期免费使用，不设企业付费版本，未来商业方案尚未确定。本文约定产品范围与验收要求；技术选型与实现方案见[技术设计初稿](agent-automation-sandbox-tech-design.md)，实施顺序见[实施规划](agent-automation-sandbox-implementation-plan.md)。

0.2 版把部署前提改为企业自部署，一个部署内支持多节点和更高并发，并以 Docker 交付；同时补充了移动端、OpenAPI 契约、MCP 与接口的关系，以及 Skill 的分发和评测。0.3 版确定了名称和许可证，增加了门槛很低的内置账号，并收窄了首版范围：企业专属功能和移动端都先从简。逐项变化见第 13 节。

## 1 产品目标与使用边界

### 已确认的方向

- 核心使用入口是 Agent、API 和 MCP。任务的创建、修改、部署和运行控制通过这些入口完成。

- HTTP API 以 OpenAPI 描述，作为平台对外能力的唯一契约，便于后续接入其他系统。MCP 和命令行工具都基于这套接口提供。

- 保留面向人的运行控制台，提供 Web 和移动端，重点呈现日志、结果、状态及必要的执行示意图。

- 不提供代码编辑器、拖拽画布、组件搭建、节点连线或传统任务配置表单。

- 需要运行 Python、TypeScript、Shell 脚本，以及调用模型 API 的任务；首期不部署模型推理服务。

- 人可以通过受限填写页保存自己的第三方 API Key、Cookie 或 Token，供指定任务使用。

- Skill 说明能力和操作规则，随版本发布；实际权限、凭证访问和资源限制由平台执行。

- 面向企业自部署。每家企业部署自己的实例，不存在由项目方运营的中心服务器；一个部署内支持多节点，以 Docker 交付。

### 首版工作假设

首版面向企业自部署：一个部署服务一家企业或一个组织的成员，支持单机和多节点两种拓扑。每个成员有自己的身份、任务及凭证访问范围，可以使用内置账号或企业单点登录。由项目方运营的云托管、面向陌生用户开放任意代码执行、跨组织多租户均未纳入首版承诺。

首版先让一个团队在一个部署里用顺。企业专属的功能，例如 MCP OAuth 授权、外部密钥服务、用户组同步、审计界面，放到 P1；移动端首版只用来查看任务进度。

Agent 是外部客户端，平台不内置聊天助手或通用规划循环。Agent 会话结束、客户端断开或换用另一种客户端后，已激活任务仍按配置运行，获授权的新会话可以继续查询和维护。

### 用户需要完成的事情

| 使用者 | 核心目标 | 主要入口 |
| --- | --- | --- |
| 个人用户 | 用自然语言让 Agent 建立和维护自己的自动化任务，随时查看结果 | 自己使用的 Agent、Web 和移动端控制台、凭证填写页 |
| 公司成员 | 使用个人凭证完成内部自动化，了解任务是否正常和失败原因 | Agent、Web 和移动端控制台、凭证填写页、企业 IM 通知 |
| 维护者 | 部署、升级、扩容、备份和排查系统，控制资源和访问范围 | 部署配置、管理 API、命令行工具、系统运行信息 |

首版成功的标志是：用户无需进入任务制作页面，Agent 即可完成一条自动化任务从建立、测试、激活到失败排查的完整流程；用户打开控制台即可判断当前情况；企业部署可以通过增加执行节点承载更多并发。

## 3 核心使用流程

### 建立一条定时 AI 任务

用户向自己的 Agent 表达目标，例如“工作日早上整理指定系统的信息，调用模型生成摘要并保存结果”。Agent 先读取平台能力与 Skill，准备脚本、依赖、参数、时区和所需凭证引用，再提交校验。

缺少凭证时，Agent 获得专用填写链接，用户在页面中提交，Agent 仅收到完成状态和可使用的凭证引用。Agent 执行一次测试，检查日志和结果，成功后激活调度，并向用户返回任务及运行详情链接。

控制台可以看到任务用途、触发频率、下次执行时间、最近运行和测试结果。整个过程不需要人编辑代码、Cron 或任务配置。

### 查看运行情况

用户打开控制台，先看到正在执行和最近失败的任务，再按任务、状态、时间筛选历史。进入某次运行后，能够定位当前阶段、耗时、错误、日志及结果；存在产物时可以预览安全的文本或下载文件。收到失败通知后，用户也可以在手机上打开同一次运行，确认状态和错误。

用户需要改变任务时，将任务链接或运行 ID 交给 Agent。任务修改和重新激活仍由 Agent 完成。

### 处理失败

Agent 根据运行 ID 读取结构化错误和限定范围的日志，识别依赖缺失、外部服务错误、凭证失效、资源不足或脚本错误。缺少输入时返回具体的凭证填写入口；修改脚本时生成新版本并测试。

重跑会创建独立运行记录，保留与原运行的关联。对外发消息、写数据等存在副作用的任务，Agent 依据 Skill 和任务约定判断是否重试；平台不默认反复重跑。

### 更新个人凭证

凭证所有者通过本人身份可访问的链接更新或撤销凭证。后续运行按任务授权获取有效版本，不需要把 Token 写回脚本。已经启动的进程不保证能够收回已注入的值；需要停止该进程时，通过运行取消能力处理。

## 4 运行控制台

控制台以 Web 为主，移动端首版只读查看任务进度（见本节末尾）。控制台用于了解任务正在做什么、是否完成以及输出在哪里。允许导航、搜索、筛选、复制链接和下载结果。任务页顶部的“立即重新触发”手动运行最新版本。有多个启用的定时触发器时，按钮展开菜单，显示各触发器的名称和执行时间，选择一项只发起一次运行；只有一个时直接运行。运行使用所选触发器的参数；没有定时触发器可选，或所选触发器未设置参数时，使用任务的默认参数。手动运行不改变原定计划。运行页的“重试”用原运行的参数再跑一次。新建任务默认允许手动执行。只有任务明确要求禁止从控制台手动触发时，Agent 才关闭该任务的手动执行。关闭后隐藏按钮，服务端也会拒绝控制台发起的手动运行。这些操作只对维护者和所有者显示。

任务页顶部根据任务状态显示“停用任务”或“启用任务”，“跳过下次”位于右上角的更多操作菜单中。跳过下一次定时执行后自动恢复原计划，同时到期的定时触发器一起跳过，Webhook 不受影响；跳过立即生效，不支持撤回。停用会关闭定时和 Webhook 触发，已排队和正在执行的运行继续完成。重新启用沿用之前激活的版本，首次启用使用最新版本，仍须满足激活前测试要求。这三项操作只对维护者和所有者显示，不受手动执行开关影响，执行前展示确认窗口。任务内容编辑和触发器配置修改仍经 Agent 或 API／MCP 完成。

任务可带多个分类标签，例如「日报」或「CRM」。Web 和移动端都在任务列表和详情中显示标签，列表支持按一个标签筛选。维护者和所有者可以在 Web 任务详情或经 API／MCP 修改标签。标签不参与执行节点匹配，修改标签不影响任务版本和触发器。

任务页的更多操作菜单提供“删除任务”，停止触发并移出任务列表，保留任务、版本及历史运行。删除不取消已经开始的运行；未手动归档的历史仍按部署的保留策略处理。维护者和所有者可在运行详情或列表预览中将已结束的运行“归档记录”，从默认列表移到“已归档”。归档后的记录、事件、完整日志和现有产物长期保留，完整日志存于数据库，不再按时间或容量自动清理；已清理的日志不能恢复。可以取消归档，恢复默认列表及原保留策略。归档不改变执行结果、任务计划或自动重试。

### 信息结构

| 页面 | 首要信息 | 可展开信息 |
| --- | --- | --- |
| 登录与注册 | 用户名和密码，或企业单点登录 | 开放注册关闭时只显示登录 |
| 概览 | 正在运行、最近失败、任务列表；每项显示最近结果及下次执行时间 | 按状态、所有者、时间筛选 |
| 任务详情 | 用途、所有者、当前版本、启用状态、触发频率与时区、上次与下次执行 | 运行历史、环境摘要、引用凭证的名称和有效状态 |
| 运行详情 | 状态、触发来源、开始结束时间、耗时、版本、错误或结果摘要 | 阶段进展、日志、文件、重跑关联、平台实际记录的工具调用 |
| 凭证填写 | 需要填写什么、供哪个任务或用途使用、授权对象、到期信息 | 个人更新或撤销入口；不开放任务编辑 |
| 个人设置 | 访问令牌、自己的凭证、通知订阅、移动端配对 | 令牌范围与到期时间、凭证授权给了哪些任务 |
| 管理设置 | 账号列表、开放注册与本地密码登录开关、执行节点 | 仅管理员可见；可以创建、停用账号和重置密码 |

失败原因和结果优先于服务器内部指标。需要排查时再展开运行 ID、退出码、环境标识等信息。没有数据时使用“尚无运行记录”“等待首次执行”等真实状态，不用虚构统计填充页面。

### 日志与结果

- 日志支持实时追加、暂停自动滚动、时间标记、stdout／stderr 区分、搜索或分页、复制和下载。

- 首屏读取有限日志，支持继续读取和重连续读；对截断、过期或未能连接的情况明确提示。

- 结果可以是文本、结构化数据或文件。Agent／脚本报告的摘要与平台验证的运行状态分开呈现。

- 进程退出成功只说明执行过程正常结束。业务是否完成以任务明确上报的结果为准；没有上报结果时，不生成成功数量或摘要。

- 结果文件按访问权限提供；不直接执行任意产物中的 HTML 或脚本。大文件以元信息和下载方式呈现。

- Token 用量、费用等只有取得可靠数据时才显示，首版不要求统计。

### 执行示意图

展示以真实运行数据为来源的阶段序列或时间线，例如“获取输入 → 调用模型 → 保存结果”。阶段名称可由 Agent 在任务中声明，状态由执行事件更新；存在明确依赖才生成对应连线。

示意图支持查看当前阶段、已用时间、失败位置和对应日志，不支持拖拽、增删节点或修改连线。任务只是一段脚本且没有阶段事件时，只显示整体状态和时间线，不推测内部步骤、完成百分比或剩余时间。

图中只显示平台实际接收到的状态。沙箱内未通过平台记录的工具调用，以及外部 Agent 的内部思考与操作，不承诺自动完整追踪。

### 移动端

移动端首版只用来查看任务进度：概览、任务详情、运行详情（状态、阶段、日志尾部、结果摘要）。登录方式是扫描 Web 控制台显示的配对二维码，或者用内置账号的用户名和密码；得到的会话只读。

首版移动端不做凭证填写、通知设置和系统推送，也不提供任何会改变任务或运行的操作。Agent 发来的凭证填写链接直接在手机浏览器中打开。系统推送需要 App 发布者的推送凭证，而部署之外不存在中心服务器，所以失败通知走 Webhook 和企业 IM。

## 5 Agent 接口与 Skill

HTTP API 以 OpenAPI 描述，是平台对外能力的唯一契约。MCP 基于这套接口提供，不包含独立的业务逻辑，也不使用独立管理员身份绕开授权；命令行工具同样由它派生。HTTP API、MCP 和命令行工具使用同一套任务、运行、权限与错误语义，控制台也读取同一份运行事实。

### 能力分组

| 分组 | Agent 必须能够完成的操作 |
| --- | --- |
| 发现 | 读取版本、能力、运行环境、可用工具及输入输出说明 |
| 准备 | 在授权工作空间读写文件、准备依赖、发现或注册工具、校验任务和环境 |
| 维护 | 创建、读取、更新任务及触发条件；比较修改前后内容 |
| 执行 | 测试、触发、启停调度、取消运行、重跑或按配置重试 |
| 观察 | 查询运行及阶段状态、分段读取日志、读取结果与产物 |
| 凭证 | 请求人填写、查询完成或失效状态、引用及撤销获授权的凭证 |
| 诊断 | 获取结构化失败原因、资源状态和关联记录 |

具体工具名称和端点见技术设计。工具说明需要足够紧凑，按需返回详细参考，避免首次接入就向 Agent 注入庞大工具清单。

### 接口行为要求

- 长任务启动后返回稳定运行 ID、当前状态和控制台链接。客户端断开或等待超时不自动取消任务；取消必须是明确操作。

- 查询支持分页或游标，日志读取支持限量、续读和可见的截断说明。支持订阅的客户端可接收状态更新，其他客户端可以轮询。

- 对创建运行等会产生副作用的请求提供幂等语义。Agent 重试相同请求不应意外创建多份运行。

- 任务更新携带已读版本，发生并发修改时返回冲突，不能静默覆盖另一会话的更新。

- 错误返回稳定类别、可理解原因和可执行下一步，例如补充凭证、修正参数、稍后重试；避免仅返回一段堆栈。

- 身份、凭证引用与资源权限在每次调用时检查。知道运行 ID 或取得链接，不等于取得访问权限。

- 日志订阅、进展事件等增强能力通过兼容性协商使用；首版完整流程不依赖某个客户端独有扩展。

- 标注操作是读取、变更还是执行，并提供校验及变更预览；不要求人每次重复确认已授权任务的正常执行。

- Agent 客户端使用绑定个人身份的访问令牌，令牌代表具体成员，权限不超过该成员。按 MCP 授权规范经 OAuth 登录放到 P1。

- 多节点部署下，Agent 连接任一服务副本都应得到一致结果，不依赖会话固定在某个副本上。

- 接口契约的破坏性变更只在新的主版本中出现，并保留过渡期。

### Skill 的职责

随发行版本提供接入、任务建立、环境准备、凭证填写、测试激活、失败诊断、部署运维和版本迁移指南，按使用场景拆成几个 Skill，避免一次加载全部内容。Skill 应教 Agent 先发现能力再操作，并在创建任务后校验、测试、检查结果，最后激活触发器。

Skill 也说明重试副作用、凭证处理和资源使用约定。服务端提供与自身版本匹配的 Skill，Agent 可以通过 API、MCP 或命令行获取；字段说明、错误类别等参考内容由接口契约生成，避免与接口脱节。

Skill 不能替代服务端授权、隔离或审计。关键约束由服务端执行，例如没有成功测试的任务版本不能激活，部署者可以关闭这项检查。每次发布前，用真实 Agent 跑验收中的 Agent 场景来评测 Skill，判断依据是服务端记录，而不是 Agent 的自述。

## 6 执行与调度规则

### 环境与任务版本

Python、TypeScript、Shell 在可识别版本的环境中运行。Agent 可以安装所需套件、执行准备命令并维护文件；工具清单说明用途、参数、版本和授权要求，供 Agent 按需发现；每次运行能够追溯任务与环境版本。一次任务的依赖安装不应静默改变其他任务的环境。

工作空间可持久保存文件和产物；单次运行使用明确的执行目录、输入与授权。任意任务不应默认获得宿主机目录、管理凭证或其他用户的工作空间访问权。平台管理进程不直接执行用户脚本。多节点下，同一任务的运行可能落在不同执行节点上，跨运行保存的数据不能依赖某一台机器的本地磁盘。

### 调度行为

Cron 必须明确时区；校验后返回人可理解的频率及后续触发时间。Webhook 需要独立鉴权、可撤销并具有有界请求规模。

首版建议默认同一任务不重叠执行；遇到下一次触发时，记录跳过原因。全局并发和队列均有上限，达到限制后返回排队、跳过或拒绝的明确结果，不无限积压。

停机期间默认不自动全量补跑，恢复后计算下一次触发；需要补跑的任务由 Agent 明确发起。定时触发按任务和计划时间去重，多个服务副本同时运行时也只建立一个实例，但不承诺外部系统副作用的严格“恰好一次”。

自动重试默认关闭，可按任务设置有限次数与等待规则。取消、人工撤销凭证等情况不自动重试。运行期间修改调度只影响后续触发，不改写已经建立的运行。

### 执行节点

执行节点负责准备环境和执行任务，可以按机器增加。节点可以带标签，任务声明需要的标签后，只由匹配的节点执行；企业可以把部分节点部署在能访问内网系统的网段。任务校验时，如果没有满足标签要求的在线节点，返回明确提示。

执行节点通过平台接口领取运行，不直接持有数据库或存储的管理凭证。节点失联时，其运行在确认无法继续后标为运行中断，不会一直显示运行中；其他节点继续领取新运行。

### 运行状态

| 阶段 | 对人的含义 |
| --- | --- |
| 排队中 | 已接受，等待执行资源 |
| 准备中 | 校验环境、输入和凭证，准备执行 |
| 运行中 | 脚本或工具正在执行 |
| 取消中 | 已请求停止，尚未确认执行进程结束 |
| 执行完成 | 进程正常结束，结果内容单独展示 |
| 执行失败 | 准备或执行失败，保留原因和错误阶段 |
| 已超时 | 达到执行时限，执行环境已停止 |
| 已取消 | 已确认停止，保留已有日志和产物状态 |
| 运行中断 | 服务或执行进程异常终止，无法继续原运行 |
| 已跳过 | 此次触发因重叠、调度策略或前置条件未满足而未执行 |

服务或执行节点重启后检查遗留运行。不能把已不存在的执行进程永久显示为“运行中”，也不能将请求取消直接等同于停止成功。需要重跑时建立新记录并关联原运行；代码改动后重跑必须显示使用的新版本。

### 日志、产物和保留策略

运行记录、日志和结果持久保存，保留周期与大小由部署者配置，不作为付费解锁项。系统达到磁盘或输出限制时，明确记录截断、清理或拒绝原因。

任务导出保留凭证引用和环境描述，不导出明文凭证。恢复与迁移保留运行关联；无法恢复的产物明确显示已过期或缺失。

## 7 凭证与访问边界

每个凭证有所有者、用途、状态以及获准使用的任务。平台支持 Key、Cookie、Token 等字符串或字段集合，不要求用户首先完成第三方 OAuth 集成。自动 OAuth 授权与续期不属于首版。

Agent 创建填写请求时说明任务和用途。填写页绑定请求、用户身份及有效期，提交后仅返回完成状态和凭证引用。普通管理接口、MCP 返回、页面地址和任务参数中不包含明文值。

凭证加密保存，备份数据和解密材料分开管理；首版解密材料来自本地密钥文件，外部密钥服务放到 P1。所有者可以更新和撤销凭证；新运行使用当时有效且已授权的版本。凭证不可用时，在执行业务动作前停止准备并报告原因。使用与授权变更记录操作者和关联任务，不记录明文。

权限至少覆盖任务查看、修改、运行，以及日志、文件、凭证使用范围。默认只开放本人资源；成员之间以项目为单位共享。首版角色分三种：查看者可以查看任务、运行、日志和文件；维护者还可以运行控制和修改任务；所有者还可以管理成员。凭证始终属于个人，由所有者授权给具体任务。平台管理员管理身份和运行环境，不以一个共享超级 Token 代替所有人的操作身份。

成员可以使用内置账号或企业单点登录。内置账号只需用户名和密码，不强制绑定邮箱，注册后即可使用；第一个注册的账号成为管理员。管理员可以在后台关闭开放注册，配置单点登录后还可以关闭普通用户的本地密码登录。管理员停用成员后，其会话和访问令牌立即失效。登录、令牌、账号与权限变更、凭证使用等关键操作写入审计日志，记录操作者和关联对象，不记录明文。

日志与常规返回对已知敏感值脱敏，包含分段输出的情况；敏感字段不进入普通运行快照。加密与脱敏不能阻止一个已经合法获得凭证的脚本主动变换或外传该值。因此，代码修改与凭证使用授权需要一起判断，首版以企业内部成员使用的自部署为边界。

沙箱执行具备 CPU、内存、执行时间、进程和输出量限制。任务终止后不应遗留后台进程。受限网络与允许挂载的范围由部署策略决定，Agent 只能在被授予的环境中使用可用工具；修改 Skill 不会扩大真实权限。

## 8 部署与容量验证

### 部署要求

平台以 Docker 镜像交付，提供两种部署拓扑：

| 拓扑 | 组成 | 适用 |
| --- | --- | --- |
| 单机 | 一个容器运行全部组件，使用 SQLite 或 PostgreSQL，以及本地存储 | 个人、小团队、试用 |
| 多节点 | 多个服务副本放在负载均衡之后，执行节点按机器扩展，使用 PostgreSQL 和 S3 兼容对象存储 | 企业部署 |

两种拓扑使用同一套程序，单机部署可以通过导出导入迁移到多节点。不强制依赖 Kubernetes、外部消息队列或缓存服务；数据库和对象存储的高可用由部署者提供。执行环境按任务需要准备，首版不默认打包浏览器、IDE、Jupyter 和大型工具全集。

提供明确版本的发行物、健康检查、升级和回退说明，以及元数据、产物与凭证解密材料的备份恢复流程。升级允许短暂停机，执行节点可以逐台升级；不停机的滚动升级放到 P1。单个任务耗尽资源或安装依赖失败，不应导致控制台和管理接口失去响应。

部署后第一个注册的账号成为管理员。公网部署时，应先完成首次注册，或预先创建管理员账号。

镜像可以同步到企业私有仓库，依赖安装可以配置内部镜像源，支持内网和离线部署。执行节点所在主机拥有容器运行时权限，建议与其他服务分开部署。

平台可以访问用户配置的外部模型和服务；控制面不强制依赖某个云端服务、商业许可证校验或持续遥测，也不依赖项目方运营的任何中心服务。

### 容量验证目标

以下数字是首版待实测的验收目标，不是现有性能结论。

单机拓扑：

| 条件 | 建议目标 |
| --- | --- |
| 试用主机 | 2 vCPU、4 GiB 内存，无 GPU；任务自身资源单独计算 |
| 验证规模 | 100 个任务定义、5 个并发轻任务、单次运行 10 万行日志 |
| 观察体验 | 正常本地网络下概览及运行详情首屏 3 秒内可用，新增日志通常在 2 秒内可见 |
| 大日志 | 首屏不加载整个文件；仍可定位末尾、继续读取和下载，不冻结页面 |
| 任务独立性 | 断开 Agent 和关闭控制台后，任务与调度继续执行 |
| 故障恢复 | 重启后保留已保存记录，识别中断运行，不重复建立同一计划时间的调度实例 |

多节点拓扑，规模暂定，待按公司实际情况确认：

| 条件 | 建议目标 |
| --- | --- |
| 试用部署 | 2 个服务副本、3 个执行节点、PostgreSQL、S3 兼容对象存储 |
| 验证规模 | 1000 个任务定义、50 个并发运行 |
| 观察体验 | 与单机一致：概览及运行详情首屏 3 秒内可用，新增日志通常在 2 秒内可见 |
| 调度去重 | 多个服务副本同时运行 24 小时，同一计划时间不重复建立实例 |
| 节点故障 | 关闭一个执行节点，其运行被识别为中断，其他节点继续执行；关闭一个服务副本，不影响控制台和 Agent 使用 |
| 扩容 | 增加执行节点后并发上限随之提高，不需要停机 |

基准结果记录应用版本、部署拓扑、执行环境、主机配置和实际资源消耗。正式发布前根据实测调整默认并发、保留策略和支持范围。

| A08 | 重叠及请求重试 | 任务执行超过触发间隔时按配置处理并留下记录；重复提交同一个幂等请求不新增运行 |
| A09 | 取消及超时 | 启动带子进程的任务，取消或超时后执行环境停止；未确认停止前不显示已取消 |
| A10 | 重启恢复 | 运行中重启服务或执行环境，历史可读，中断状态可识别，同一计划触发不重复建立实例 |
| A11 | 失败排查 | Agent 能按运行 ID 获取错误、阶段、限定范围日志和结果，修正后创建关联的新运行 |
| A12 | 版本冲突 | 两个 Agent 会话修改同一任务，过期版本被明确拒绝，原有运行保持原配置记录 |
| A13 | 大日志与断线 | 10 万行日志仍可分段浏览；重新连接可以续读，截断或过期范围可识别 |
| A14 | 工具与隔离 | Agent 发现并调用可用工具；越界目录、未授权凭证及超出资源限制的操作被服务端限制 |
| A15 | 备份恢复 | 将备份恢复到新实例后，任务、触发器、访问范围和凭证引用可继续使用；不需要在脚本内重新填写明文 |
| A16 | 通知 | 故意令任务失败，收到包含实际状态、原因摘要和运行链接的通知，通知内容没有凭证明文 |
| A17 | 移动端观察 | 用户扫码配对后，在手机上从概览进入某次运行，看到状态、阶段和日志尾部；移动端会话无法执行任何写操作 |
| A18 | 账号与 Agent 授权 | 新用户不填邮箱即可注册并登录；管理员关闭开放注册后无法自助注册；成员可以通过企业 OIDC 登录；Agent 通过访问令牌以该成员身份操作，权限不超过该成员；管理员停用成员后，其会话和令牌立即失效 |

多节点部署另需通过以下场景：

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| B01 | 多副本调度 | 3 个服务副本同时运行 24 小时，同一计划时间没有重复运行 |
| B02 | 执行节点故障 | 运行中强制关闭一个执行节点，确认失联后运行标为运行中断，其他节点继续领取新运行 |
| B03 | 服务副本故障 | 关闭一个服务副本，Agent 和控制台经其他副本继续使用，日志续读不丢失 |

发布前以这些场景验证首版闭环。验收使用实际执行和故障注入，不能以返回成功响应或控制台存在对应页面代替。

| 日志、文件保留默认值 | 提供可配置策略；根据试用磁盘与使用频率确定默认值 |
| 首批工具套件 | 优先 Python、TypeScript、Shell、HTTP 和文件；更多能力按首批真实任务加入 |
| 多节点容量目标 | 暂按 1000 个任务、50 个并发运行验证；根据公司实际规模调整 |
| Kubernetes 执行器 | 暂列 P1；如果首批企业部署依赖 Kubernetes，再调整优先级 |
| 移动端系统推送 | 首版不做；失败通知走 Webhook 和企业 IM |
| 项目级共享凭证 | 首版只支持个人凭证 |
| Windmill 迁移范围 | 以实际任务、依赖和凭证引用盘点为准，暂不承诺无修改迁移 |

这些选择不阻止先完成核心产品闭环，但会影响正式发布的默认配置和支持承诺。
