# 未发布：跨运行状态与 runner 协议 2

本变更尚未发布，也不沿用 0.9.0 已完成的人工审查或目标主机验证结论。新迁移、私有协议、租约、文件路径与权限、Skill 服务端约束需要审查；不要只替换单个 server 后立即恢复新任务领取。

任务可以在 `/sbx/state` 保存游标和小文件，同一 TaskID 的版本与 runner 共享。输入在领取时固定，只有进程退出码 0 的完成运行才发布完整快照，测试运行也会发布。失败、取消、超时保留旧值，正常空目录会清空；并发以最后成功提交的事务覆盖。上限为 10 MiB、1000 项和每路径 255 个 UTF-8 字节，不接受链接或特殊文件。

迁移 `20261110010000_task_state` 新增当前快照与运行输入／输出引用。实例备份和整库导出包含状态；单任务 TaskBundle 仍不包含运行状态。旧实例初始状态为空，不自动转换旧工作目录。回退迁移会删除状态引用，需保留升级前的数据库、对象存储和主密钥备份。

内部 runner 协议升为 2，公共 API 保持不变。版本 1 可完成已经领取的运行，新领取只允许版本 2；新版 runner 遇到旧 server 会明确拒绝，不静默降级。按[部署文档第 8 节](../deploy.md#8-升级与回退)先停领并排空，完成全部 server 与迁移的升级，再升级 runner 并恢复领取。首次上线不支持与旧 server 混合领取，内嵌 runner 也受此限制。

领取脚本工具时，慢对象读取可能跨过运行租约。读取完成后会按当前归属、状态和租约筛选整批分配；晚到的读取错误不会覆盖已经对账为“运行中断”的终态。失败转移在事务末尾再次检查租约，失效时整笔事务回滚，包括失败状态、错误和结束时间、事件及引用释放，不发送终态通知。此修复没有新增协议字段、迁移或依赖，归属与租约边界仍需审查。

验证入口：`runproto` 编码边界、`service` 的租约／事务／GC 测试、`runner`／`runnerhttp` 的安全和重试测试、`ops` 的备份导入导出测试，以及 `tests/acceptance/state_test.go` 的真实跨节点、跨运行时和备份恢复场景。最终验证范围与尚未覆盖的目标环境，以本次交付记录为准。
